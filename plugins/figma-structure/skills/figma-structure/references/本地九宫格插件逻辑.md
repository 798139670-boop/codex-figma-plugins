# 本地九宫格插件逻辑（nine-slice-recode-local）

本文件根据用户提供的本地插件文件生成：

```text
G:\a_项目\new插件\manifest.json
G:\a_项目\new插件\dist\code.js
G:\a_项目\new插件\dist\ui.html
```

它是对插件实际行为的工作契约，不是对其他 Figma 社区插件的泛化说明。

## 1. 插件身份与运行边界

- `manifest.json`：`name=九宫格插件`、`id=nine-slice-recode-local`、`api=1.0.0`。
- 入口：`dist/code.js`；界面：`dist/ui.html`。
- 仅声明 `editorType=[figma]`，无网络权限，`allowedDomains=[none]`，文档访问模式为 `dynamic-page`。
- 必须在 Figma Desktop 中通过本地 manifest 加载；不能用同名社区插件替代。
- 插件每次只处理当前选中的一个节点。选择数量不是 1、节点不可导出、节点位于 Instance 内部时，插件会拒绝处理。

## 2. 选中节点与源图读取

1. 读取当前选中节点；若节点已经是插件生成的 `origin`，优先解析其保存的切片数据和源尺寸。
2. 对普通节点使用 `exportAsync({format:"PNG", constraint:{type:"SCALE", value:1}, contentsOnly:true})` 读取完整源图。
3. 插件解析 PNG 的 IHDR，要求位图尺寸有效；最大边为 4096 像素，总像素不超过 16,777,216。
4. 为避免超限，首选栅格倍率为 10，但会按最大边和总像素自动降低；所有九个切片必须使用同一栅格倍率。
5. 已处理源可选择：
   - `stored`：使用首次处理时保存的源图和源尺寸；
   - `current`：重新读取当前九宫结构的完整图，再处理。
6. 若选择结构发生变化、节点被删除或节点不再是 `origin`，本次操作必须中止，不能继续写入。

## 3. 边界值与切片设置

- 普通源的默认边距为源宽/高的 10%，每个值四舍五入到 0.1。
- 边距按 `left, top, right, bottom` 解释，并被限制在源尺寸可容纳的范围内：左右不能使中间宽度小于 1，高下不能使中间高度小于 1。
- UI 同时支持按比例和按像素编辑四个边距；Reset 恢复默认 10% 值或已保存的有效值。
- `fillMode` 只有 `stretch` 和 `tile`：
  - `stretch`：所有非零区域使用 CROP 图像填充；
  - `tile`：角仍使用 CROP，边和中心使用 TILE；插件为 TILE 区域写入对应 scaling factor。

### 3.1 横向三宫

该插件没有独立的“3-slice”开关。要生成横向三段，必须把 `top=0,bottom=0`，只设置 `left/right`；输出有效切片位于中间行：

```text
slice-1-0  slice-1-1  slice-1-2
```

零高度行不创建有效矩形。若上下边距不是 0，就不能把结果报告为纯横向三宫。

### 3.2 纵向三宫

要生成纵向三段，必须把 `left=0,right=0`，只设置 `top/bottom`；输出有效切片位于中间列：

```text
slice-0-1
slice-1-1
slice-2-1
```

若左右边距不是 0，就不能把结果报告为纯纵向三宫。

## 4. 插件生成的节点结构

- 插件始终按 3×3 网格计算，切片名使用 **0-based** 的 `slice-row-col`，范围为 `slice-0-0` 到 `slice-2-2`；三宫只保留有效的中间行或中间列。
- 输出根默认是真实 `COMPONENT`（UI 默认“打成组件”开启）；关闭后输出 `FRAME`。
- 根使用源尺寸建立切片坐标，之后恢复/适配目标根的原始显示尺寸；因此消费尺寸可以不同于源尺寸。
- 每个有效切片是 `RECTANGLE`，直接位于输出根下，使用 IMAGE Fill，通常 `scaleMode=CROP`；切片被锁定。
- 约束由行列位置自动写入：
  - 列：`MIN / STRETCH / MAX`；
  - 行：`MIN / STRETCH / MAX`；
  - 四角双轴固定，边单轴拉伸，中心双轴拉伸。
- 插件在根节点保存 shared plugin data：

```text
9slice/type=origin
9slice/sliceData=[left,top,right,bottom]
9slice/sourceSize=[width,height]
9slice/sourceRasterScale=<number>
9slice/formatVersion=2
9slice/fillMode=stretch|tile
```

- 切片保存 `9slice/type=frag`。这些切片是结构实现层，不应分别设置 PNG Export。
- 插件不会自动设置 Figma 右侧 `exportSettings`。需要 PNG Export 时，必须在插件完成后按项目规则单独设置，且只能设置在资源根或明确的最终静态源上。

## 5. 保留源结构与组件身份

- 插件 UI 默认 `preserveSource=false`、`createComponent=true`。
- 本项目的安全执行默认覆盖插件的破坏性默认值：除非用户明确允许删除/替换原始源，否则必须把“保留源结构”打开。
- 保留源时，插件会把原节点放入隐藏、锁定、名为 `NotExport` 的备份 Group，并写入备份快照；正式组件放回原始兄弟位置。
- 不保留源时，插件会删除/替换原始节点。此模式只在用户明确授权并且已有可验证的正式替代物时使用。
- 将 `FRAME` 与 `COMPONENT` 互换会改变节点身份；插件要求确认。Skill 不得绕过该确认，也不得为了组件化 Detach 远程/Common Instance。
- 已存在的插件 `origin` 可原地重切；如果组件/Frame 类型与 UI 选择不一致，应先报告身份变化风险。
- 处理完后必须验证：原始视觉备份（若开启）、正式组件、切片直接子级、Instance 引用和原显示尺寸均存在。

## 6. Skill 的强制执行顺序

```text
审计源节点
→ 确认三宫/九宫方向和边界
→ Figma Desktop 加载 G:\a_项目\new插件\manifest.json
→ 单选源节点运行“九宫格插件”
→ 设置边距和 stretch/tile
→ 打开“保留源结构”、确认“打成组件”
→ 确认生成
→ 回读 origin、slice-*、约束、尺寸和备份
→ 仅在项目要求时设置资源根 PNG 1x Export
→ 建立图片 Section 资源源
→ 用真实 Instance 替换 View 中同源原图
→ 截图和结构指纹复核
```

任何一步失败都必须停止写入并报告具体错误；不能用手工创建的相似矩形、截图或普通 PNG 代替插件生成的切片树。

## 7. 验收清单

- [ ] 使用的 manifest、`code.js`、`ui.html` 路径与本文件一致。
- [ ] 处理前只有一个选中节点，且不在 Instance 内部。
- [ ] 源尺寸、目标尺寸、栅格倍率和边界值已记录。
- [ ] 九宫有 9 个有效切片；横向/纵向三宫的正交边距确实为 0。
- [ ] 切片命名为 0-based `slice-row-col`，没有误写成 1-based。
- [ ] 切片直接位于资源根下，约束符合 MIN/STRETCH/MAX。
- [ ] 切片没有独立 PNG Export，父子没有重复 Export。
- [ ] `origin` shared data 可回读，三宫/九宫方向与 `sliceData` 一致。
- [ ] 组件身份、源备份、View Instance 引用和显示几何闭环成立。
- [ ] Figma Export 配置作为插件后的独立步骤完成并回读，不把插件完成误报为 Export 完成。
