# 参考驱动的 Figma 结构整理

当目标节点需要对齐另一个“正确结构” Section 时，参考只用于确定导出语义和层级职责。目标的业务名称、文案、美术和当前尺寸仍是事实来源，除非用户明确要求改名或改视觉。

## 结构差异审计

先为目标和参考建立同一格式的树快照，至少包含：节点类型、真实 Instance 身份、父子边、同级顺序、可见性、Auto Layout、Clip content、绝对 bounds、Export，以及行为根和命中区域。按职责对齐，而不是按字符串对齐：

- 页面根、背景、汇总/信息容器、列表/ScrollView、单项模板、点击层、进度条、奖励按钮、底部导航分别比较。
- 把差异标为“必须补齐的导出语义”“应复用的已验证 Common”“只影响组织的层级差异”或“仅视觉/尺寸差异”。
- 参考节点的名称、编号、样本数量和尺寸不能当作通用常量；不要因为参考有 `Root` 就在目标内部新增另一个可能被识别为 UIRoot 的节点。

## 保持目标命名的结构修正

用户要求不改命名时，保留现有节点名称和后代关系中仍有业务意义的名称。通过新增 wrapper 或调整父子关系表达缺少的语义：

```text
List（保留目标原名）
└─ 目标原名的首个模板 Item
   ├─ 目标原有视觉容器
   ├─ Btn_click          # 覆盖预期 Rect，仍需核验实际命中机制
   └─ NotExport          # 仅用于已确认的非正式内容或备份
```

`Btn_click` 应覆盖预期点击 Rect，不能遮挡需要接收事件的上层控件；若已有可绑定背景能覆盖整个 Rect，则不重复造视觉。核验实际可绑定的 Graphic/HitArea，或参考中已有文档依据的命中机制；同尺寸空 Frame 本身不能证明可点击。缺少依据时保留结构占位并记录命中区 unresolved，不声称已完成交互。

`NotExport` 是导出压制，不能等同于 `visible=false`。演示副本应保持原可见状态、Auto Layout 占位和绝对几何，避免列表塌缩或设计稿缺项；只有已经存在正式替代的重叠备份需要不可见。红点/徽章应先归属正确 Item，只有参考或用户范围确认其为示意内容时才压制，正式运行时状态不得自动收进 `NotExport`。

占位节点只表达插件需要的绑定槽位。没有现成视觉或 Common 身份时保持空结构并记录 unresolved，不新增虚构图标、文案或状态。

## Common 与 Instance 边界

先区分玩法/当前模块组件与 Common。用户或当前模块上下文已确认属于玩法内的真实 Instance，应保留并核验自身定义或参考中的组件身份；不能因为 Common 中没有匹配就迁移、替换或 Detach。Figma 来源一致与 Unity Prefab 可解析是两项验证，后者未验证时单独报告。

每次任务从配置或用户本轮 URL 动态读取 Common，并按 component key、component ID、节点 ID、唯一标准化名称依次匹配。视觉相似、截图相同或 bounds 相同都不足以证明公共组件身份。

- 分别记录 Figma 节点类型与导出 Role。`Image_*` 不会改变 `INSTANCE` 的组件身份，但显式 Role 仍优先于 Instance 自动推断的 Reference；不得把两者混为一谈，也不能仅凭前缀决定 Detach。
- 带有效 PNG Export 的 Instance 直接保留为图片源；不要为了“统一结构”拆解或替换它。
- 无 PNG 的 Instance 命中 Common 时保留真实 Instance。仅当本轮完整 Common 索引确认无匹配，且 Clone + Detach 已在授权计划内时，才按主文件的 fallback 处理并保留不可见原件备份。索引不可访问、身份缺失或匹配歧义属于 unresolved，不能当作已确认无匹配；存在 Common 复用要求时也不能默默改走 Detach。
- 用户明确要求“同样美术必须复用公共组件”时，只有动态索引确认身份后才插入 Common Instance；确认失败就保留原节点并报告，不能凭外观猜测。
- 插入或替换后恢复原目标的绝对 bounds、同级位置、布局 sizing 和实例尺寸参数；固定组件保持源比例，响应式组件才使用 `@size`/Stretch。

## 动态视觉与 PNG

进度、货币数值、奖励数量、状态文字和本地化文案属于运行时数据，必须留作独立结构节点。ProgressBar 的 `Image_fill` 源应覆盖完整 track，由 UGUI 的 fill/amount 驱动；不能拿设计稿中当前 40% 或 60% 的裁剪图当最终 Sprite，也不能把动态值烘进背景 PNG。

对结构根补背景时，保留原静态外观的完整属性（fills、strokes、圆角、effects、opacity、blend mode）。PNG Export 只放在最终不可再拆的静态视觉源；Button、ProgressBar、List、ScrollView 等行为/布局根保持无 PNG Export。移动或包裹分支后检查是否产生父子重复 Export。

## 二次核验

写入后重新读取目标和参考，确认：

1. UIRoot 数量不变，正式导出树的父子边、顺序、角色 wrapper 和模板池符合结构差异计划；
2. 关键控件的命中区、进度条完整 track、Common Instance 身份、NotExport 压制和 PNG 位置正确；
3. 绝对 bounds、Auto Layout、Clip content 和可见层级保持设计意图；
4. 截图或渲染对比中没有双背景、丢失描边、错位或新增未授权视觉；
5. 最终指纹与计划一致，任何剩余差异、未解析 Common、字体限制或参考冲突都列入 warnings/needsUserDecision。
